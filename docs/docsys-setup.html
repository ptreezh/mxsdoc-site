2.2 修复 jdbc.properties

问题：默认 jdbc.properties 使用 ${catalina.home} 占位符，Tomcat 启动时未展开导致 DB 连接失败。

修复（必须）：

文件：F:\gy\docsys-2.02.87\docsys\tomcat\webapps\DocSystem\WEB-INF\classes\jdbc.properties

db.type=sqlite
db.driver=org.sqlite.JDBC
db.url=jdbc:sqlite:F:/gy/docsys-2.02.87/docsys/tomcat/DocSystem.db   # 把 ${catalina.home} 替换为绝对路径
db.username=
db.password=

2.3 启动服务

# 双击或命令行
F:\gy\docsys-2.02.87\docsys\start.bat

等待 30-60 秒后访问：http://localhost:8100/DocSystem/web/

⚠️ 端口：默认 8100（不是 8200），具体查看 tomcat\conf\server.xml

3. 超级管理员初始化

3.1 数据库自动初始化

DocSys 启动时会自动建表（SQLite 27 张表）。访问 http://localhost:8100/DocSystem/web/：

  • 如果 getLoginUser 返回 needAddFirstAdmin → 系统自动弹出"创建第一个管理员"面板
  • 如果返回 系统管理员不存在! → 面板已显示

3.2 通过前端添加（首次）

系统会自动调用 showAddFirstAdminUserPanel()，填写：

字段值
账号 (userName)admin
密码 (pwd)admin@12345（前端会 base64 编码发送）
邮箱 (email)admin@yourdomain.com
手机 (tel)13800138000

点击「添加」按钮 → 系统调用 addFirstAdminUser API 写入 user 表。

3.3 通过 SQLite 手工初始化（备选）

如果前端 addFirstAdmin 流程异常，可直接通过 SQLite 写入：

sqlite3 F:\gy\docsys-2.02.87\docsys\tomcat\DocSystem.db

# 插入超管（前端 base64 编码密码后再发送，所以 DB 中存 base64）
UPDATE user SET PWD='YWRtaW5AMTIzNDU=' WHERE NAME='admin';
# 其他用户（密码=明文 base64）
UPDATE user SET PWD='ZWRkaXRvckAxMjM=' WHERE NAME='editor01';
⚠️ DocSys 登录密码机制：前端 pwd : base64_encode(明文密码) 发送，服务器比对 DB 中存储的密码。当前实测手工 base64 仍报"密码错误"，可能涉及更复杂的哈希/盐，建议走 install.html 引导流程让系统自动创建管理员。

6. 常见问题排查

6.1 端口被占用

# 改 server.xml：<Connector port="8100" protocol="HTTP/1.1" />
# 文件：F:\gy\docsys-2.02.87\docsys\tomcat\conf\server.xml

6.2 DB 连接失败

  • 检查 jdbc.properties 占位符是否替换（参见 2.2）
  • 检查 DB 文件目录是否存在且有写权限
  • 查看日志：F:\gy\docsys-2.02.87\docsys\tomcat\logs\docsys.log

6.3 登录密码错误

  1. 优先使用 install.html 引导流程（http://localhost:8100/DocSystem/web/install.html）
  2. 检查前端 base64 编码：浏览器 F12 → Network → login.do → Form Data → pwd 字段
  3. 检查 DB 中 PWD 字段格式：与前端发送的 base64 是否完全一致

6.4 Tomcat 启动慢

首次启动需加载 27 张表 + 250+ jar，可能 30-90 秒。可查看 logs/catalina.2026-09-27.log 跟踪进度。
